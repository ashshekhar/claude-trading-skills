# Security Policy

## Reporting a vulnerability

Please do not include credentials, private portfolio information, or exploitable
details in a public issue. This repository does not publish a private contact
address, and this file does not confirm that GitHub private vulnerability
reporting is enabled. Check the repository's **Security** tab for a private
reporting option before using it. If none is available, obtain a maintainer's
private reporting channel through a contact you already know to be private;
do not send sensitive details through a public issue or discussion.

When you can report safely, include the affected file or feature, the exact tag
or commit SHA, impact, and steps to reproduce with synthetic data. Do not attach
real credentials, session logs, account data, or broker exports.

## Supported versions

This project has not published a supported-version matrix or a policy for
maintaining older releases. A supported-version claim is therefore unconfirmed.
Include the exact tag or commit SHA when asking about a version. Do not assume
that a branch, fork, or old commit receives security fixes.

## Data handling

See the [English data handling guide](docs/en/privacy-data-handling.md) and
[Japanese guide](docs/ja/privacy-data-handling.md) for the repository's local
data inventory, external provider boundaries, session-log miner behavior,
retention limits, and backup/recovery instructions.
